## 隧道失联故障修复（同日 23:05–23:10）

- 用户反馈公网地址 `lottery-relation-archives-files.trycloudflare.com` 不工作。排查结论：**本地服务与数据库全程正常**（finance.exe pid 59792 监听 0.0.0.0:8081、`/api/meta` 返 401、`integrity_check ok`、`user_version=3`、entries 4 / stock_items 14 / movements 14），故障只存在于隧道出口。
- 直接原因：cloudflared 从 22:50 起持续 `dial tcp 198.41.x.x:7844: i/o timeout`，隧道迟迟连不上边缘，Cloudflare 遂回收临时域名 → DNS 变 NXDOMAIN（nslookup 报 Non-existent domain），所以浏览器表现为「打不开」而非「502」。
- 根因：终端环境里注入了 `HTTP_PROXY/HTTPS_PROXY=http://127.0.0.1:32014`（沙箱 `sandbox-cli.exe` pid 52100），cloudflared 会继承该代理，而代理白名单不放行 7844；同时实测**直连** `198.41.200.53:7844` 是通的（`/dev/tcp` 连接成功）、`https://www.cloudflare.com` 也是 200。
- 修复两处（`scripts/start.sh`）：① 启动 cloudflared 时用 `env -u HTTP_PROXY -u HTTPS_PROXY -u ALL_PROXY -u http_proxy -u https_proxy -u all_proxy` 清掉代理变量直连边缘；② 新增 `tunnel_reachable()` 健康检查 —— 原来只判断「PID 存在」就把隧道当成好的（这次正是 PID 活着但隧道已死），现在 pid 在但公网不可达会自动停掉重建。
- 重跑 `bash scripts/start.sh`：服务复用 pid 59792，隧道删旧建新，新公网 `https://gzip-arizona-bureau-physical.trycloudflare.com`，`Registered tunnel connection ... protocol=http2 location=lax01`；实测首页/手机页均 401（口令校验生效，请求已到后端）。
- 教训：quick tunnel 的「进程还在」不等于「服务还在」；隧道失联后域名会被回收，必须换域名。启动脚本现在能自愈，但域名仍会变。

## 固定入口网关（同日 23:27 起）

- 需求：quick tunnel 域名每次都变，想要一个**固定地址**。方案定为「网关反向代理」而不是「302 跳转」——跳转会暴露随机域名、让 `finance_access` Cookie 跨源失效、坏掉 PWA。
- 网关独立项目 `C:\Users\WangXin\WorkBuddy\gateway`：**纯标准库 Go（零第三方依赖、go 1.21）**，`net/http` + `httputil.ReverseProxy`。注册表用 JSON 文件（`data/registry.json`）而不是数据库——它是**可重建缓存**，程序每次启动和每 30 秒上报，重启后一个周期自愈。这样沙箱里绝不会卡在 `go mod` 下载。
- 关键实现（`proxy.go`）：strip 前缀转发、`pr.Out.Host` 改成上游、删 `Accept-Encoding` 让 Transport 自动解压以便重写 HTML、重写 `Location`（绝对地址换 host 加前缀）、清空 Cookie `Domain` 并把 `Path` 收拢到 `/{prefix}`、`GET /finance` 301 到 `/finance/`。**代理不走 `HTTP_PROXY`**（与 cloudflared 同一个坑）。
- 已处理并验证的坑：前端全是绝对路径（`/api/` 41 处、HTML 3 处），全部改成相对路径后 `/finance/` 与根路径 `/` 同时可用，后端一行没改。本地实测：301 ✓、API 401→200 ✓、静态资源 200 ✓、`Location: /finance/` ✓、`Set-Cookie: finance_access=...; Path=/finance` ✓、登录表单 `action` 重写 ✓。
- 发布：`发布为应用` 沙箱支持 Go 单端口、能出网。链接 `https://wbapp-zkmvjjcjly9s7dgylmnivh.app.workbuddy.host/?sharecode=QPFVA7KHN2`，沙箱内反代 `https://example.com` 实测成功（出网 + 反代链路通）。**分享链接必须带 `?sharecode=`**，首次访问会种 `__wb_rsc` Cookie（30 天、Path=/），之后子请求自动携带。
- 上报接入：`scripts/start.sh` 新增 `report_gateway`（支持 GATEWAY_URL 带查询串、不加 `--noproxy`），并在 `while svc_up` 循环里每 2 分钟比对 `tunnel_url_from_log`，隧道重连换域名会自动重新上报。配置在 `.env` 的 `GATEWAY_URL/TOKEN/PREFIX/NAME`。
- **本机环境坑（新增）**：`gateway/` 目录下 `go build` 出来的 exe 被安全策略锁死（执行 126、后续连读都 Permission denied，PowerShell `Test-Path` 也拒），连复制到 `scripts/bin` 也一样。因此发布走 `gateway-deploy/` 纯源码目录，改完代码用 `bash gateway/sync.sh` 同步。
- **沙箱存活实测结论**：`/_gw/health` 的 `uptime` 从 2m22s 归零到 0s、`entries` 回 0，说明沙箱**会被回收重启**；但分享链接不变、请求仍返回 200，属「按需唤醒」而非持续 502。据此补上设计缺口：`start.sh` 改为**每 2 分钟无条件心跳重报**（原来只在域名变化时上报，沙箱重启后会一直 404），失败/成功静默、仅异常打印。
