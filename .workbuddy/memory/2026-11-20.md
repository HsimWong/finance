## 移动端页面改版：账单详情 + 总览二级页
- 用户要求三点：①账单页不能出现记账拍照入口；②每条账单可点进去看截图/标签/预算归属；③「我的」改「总览」，聚合预算、使用情况、计划、库存等电脑版能力，点进去看二级页。
- **根因（重要）**：`mobile.css` 里 `.view{display:grid}` 是作者样式，覆盖了浏览器默认 `[hidden]{display:none}`，导致三个一级视图其实一直同时显示——账单页上方就是拍照入口。已加 `[hidden]{display:none !important}`，这才是「账单页不显示拍照」的真正修复；以后任何 `hidden` 切换都依赖这条。
- 二级页做成全屏 `.sheet`（z-index 60，盖住底部 tab），用 `history.pushState` + `popstate` 支持 Android 返回键；返回按钮走 `history.back()`。
- 账单详情用 `GET api/entries/{id}`（Entry 已含 tags/allocation_name/screenshot_id），预算明细再按流水月份查 `api/allocations?period=`，截图用 `api/screenshots/{id}/image`（相对路径、同域 Cookie）。
- 总览四个卡片数据来自 `api/dashboard?period=`、`api/plans`、`api/stock/summary`；二级页：预算=资金预分配+预算明细，使用情况=收支/结余+分类支出，计划单=状态/关联预算/进度，库存=汇总+临期+在库物品；另加「基础数据」二级页（复用 `/api/meta`）。

## APK 默认进桌面版修复（1.1）
- 用户反馈：手机 APK 点进去默认不是移动端。根因：1.0 启动加载入口**根路径** `/finance/`，是否跳 `mobile.html` 完全依赖后端 `isMobileUA` + 无 `finance_desktop=1` cookie；WebView UA、残留 cookie、登录 `__auth` 成功后的 `redirectRel("./")` 相对回跳到根路径，都可能落到桌面版。本地 curl 实测：带 Android WebView UA → 302 mobile.html，但带 desktop=1 cookie → 200 桌面版，证实是间接判断不可靠。
- 修复（APK 端自包含，不动后端）：`MainActivity` 启动直接 `loadUrl(BASE_URL + "mobile.html")`；新增 `isDesktopLanding()`，在 `shouldOverrideUrlLoading`（两重载）+ `onPageFinished` 里把所有指向桌面首页的导航拉回移动版——服务端 302 由 WebView 内部跟随不触发 shouldOverride，必须靠 onPageFinished 兜底登录回跳。`versionCode` 1→2，`versionName` 1.0→1.1。
- 产物 `dist/家庭记账-1.1.apk`（34K），同密钥覆盖安装可行；aapt2 确认 versionCode 2、DEX 同时含 `mobile.html`（启动）与根路径（判断用），apksigner v2 验签通过。
- 注意：`dist/家庭记账-1.0.apk` 仍留着（历史版本）。以后改 APK 都要递增 versionCode。
