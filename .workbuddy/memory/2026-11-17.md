# 2026-11-17 工作日志

## 手机打不开 finance 站 + 极简上传页 + 手机上看电脑版

**现象**：手机上打开 https://47.94.236.198/finance/ 只出来口令页，输完口令就 404；之前有的"上传账单"极简页也进不去。

**根因（三个都跟子路径反代有关，Nginx 是 `location /finance/ → 127.0.0.1:8081/`，后端看到的路径已被剥掉 /finance 前缀）**：
1. `auth.go` 登录表单 `action="/__auth"` 是站点根绝对路径 → 浏览器 POST 到 `https://host/__auth` → Nginx 没有该 location → **404**。桌面端因为早就有 access cookie，一直没暴露。
2. `main.go` 手机跳转 `http.Redirect(w, r, "/mobile.html")` 同样是绝对路径 → **404**。
3. `mobile.html` 的「电脑版」链接写的 `?desktop=1`，在 `/finance/mobile.html` 下只会解析成 `/finance/mobile.html?desktop=1`，**原地重载**，永远进不了电脑版。

**关键坑：不能用 http.Redirect 做相对跳转。**
Go 的 `http.Redirect` 会把相对路径按**后端看到的** `r.URL.Path`（这里是 `/`）拼成绝对路径，于是 `"mobile.html"` 变成 `Location: /mobile.html`，前缀照样丢。
正确做法是自己写头：
```go
func redirectRel(w http.ResponseWriter, loc string, code int) {
    w.Header().Set("Location", loc) // 原样写相对路径，交给浏览器按真实地址解析
    w.WriteHeader(code)
}
```

**改动**：
- `auth.go`：表单 `action="__auth"`；登录成功/GET 跳转改 `redirectRel(w, "./", 302)`。
- `main.go`：手机跳转改 `redirectRel(w, "mobile.html", 302)`；新增 `finance_desktop` Cookie（180 天）记住"我要电脑版"；`wantsDesktop()` 里 **`?desktop=` 显式参数优先于 Cookie**，否则点「手机版」会被上次存的 Cookie 盖掉。
- `mobile.html`：「电脑版」→ `href="./?desktop=1"`。
- `index.html` + `style.css`：顶栏加 `.mobile-switch`（仅 ≤720px 显示）→ `href="./?desktop=0"` 回极简页。

**部署踩的雷（务必记住）**：`detectRoot()` 原来只用 `runtime.Caller(0)`，即**编译机的源码路径**。Windows 交叉编译的二进制扔到服务器后，根目录被解析成 `C:/Users/WangXin/...`，导致 `.env` 读不到 → **鉴权静默关闭**、静态目录不存在、DB 指向不存在的路径（真库没被碰，但在服务器根上误建了一个空库 `/C:/...`，已确认只有 3 个 21:56 新建的空文件后删除）。
- 已修：`detectRoot()` 改为**优先按可执行文件位置**找 `<root>/src/frontend`，找不到再退回 `runtime.Caller`。
- 已加固：`finance.service` 的 ExecStart 显式加 `-root /home/admin/finance`（并补 `WorkingDirectory`）。改 systemd 前已备份原 unit。

**验证（全部通过，经公网 https + /finance 子路径）**：未登录手机 → 口令页 action 为相对；提交口令 → 302 `Location: ./`；已登录手机 → 落到 `/finance/mobile.html`（标题 记一笔·家庭账本）；`?desktop=1` → 电脑版首页；`?desktop=0` → 回极简页；电脑 UA 直连首页；`api/meta`、`api/entries` 均 200。
