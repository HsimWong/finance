# 功能清单与交互设计（一期）

## F1 截图上传

- 前端拖拽 / 选择图片（jpg、png、webp），`multipart/form-data` 上传到 `POST /api/screenshots`。
- 服务端校验类型与大小（默认上限 10 MiB），原始字节写入 SQLite `screenshots.data`（BLOB）。
- 上传后返回 `screenshot_id`，状态为 `pending`（待整理）；预留 `parsed` / `ignored` 状态给二期自动识别。
- 截图列表可回看原图（`GET /api/screenshots/{id}/image`）。

## F2 收支流水

- 一条流水字段：类型（收入/支出）、金额、发生时间、成员、分类、标签（多个）、关联预分配、关联截图、备注、来源。
- 来源 `source`：`manual`（手录）、`screenshot`（截图录入）、`auto`（二期自动获取）。
- 支持编辑与删除；分类留空即为「未分类」，会进入报警表。
- 金额一律以**整数分**存储与计算，避免浮点误差。

## F3 细分领域分类树 + 标签（关键设计）

用户举的三个查询例子性质不同，单层分类无法同时满足，因此采用**双维度**：

| 查询例子 | 维度 | 实现方式 |
| --- | --- | --- |
| A 人员「外卖」某段时间花了多少 | 成员 × 分类 | `categories` 支持父子层级，如 `餐饮 > 外卖` |
| 全家「交通」支出多少 | 分类（含子树汇总） | 查询时展开分类子树再聚合 |
| 「猫咪」花了多少钱 | 跨领域对象 | `tags` 多对多标签，如 `猫咪`、`房租`、`保险` |

- 分类树挂在「领域」上，是账目的主归类；标签是横向切片，可跨分类共用。
- 一条流水必须（且只能）属于一个最末级分类或留空；可挂任意多个标签。
- 这样「猫咪 + 医疗」「猫咪 + 食品」也能分别查，而不必建两套分类。

## F4 多维查询

- 筛选条件可自由组合：成员、分类（含子树）、标签、类型、时间起止、未分类、关联预算。
- 返回明细 + 合计金额，并支持按「成员 / 分类（含子分类汇总到顶级领域）/ 末级分类 / 标签 / 月份 / 日期」分组聚合。
- 口径说明：按标签分组时，挂了多个标签的一笔流水会在各标签下分别计入（横向切片统计），分组合计可能大于流水总额；按分类、成员、月份分组不重复计数。未指定类型时收入与支出会合并求和，查支出请显式选「支出」。
- 前端提供查询表单与结果表格，避免每次都要写 SQL。

## F5 小荷包预分配与进度

- 每月两批：`月初` / `月中`，对应 `period = YYYY-MM`、`batch = first | mid`。
- 一条预分配：名称、目标分类（可选）、预算金额、备注。例：`2026-11 / 月初 / 房租 / 4000.00`。
- 流水通过 `allocation_id` 关联到预分配；进度 = 该预算下已支出合计 / 预算金额。
- 状态：`未动用` / `进行中` / `已用完` / `超额`；总览面板按批次展示进度条。

## F6 总览面板

- 本期总收入、总支出、结余。
- 收入资金使用进度：本期预分配总额、已使用、剩余，以及各预算的进度条。
- 未分类流水数量（点击进入报警表）。
- 最近流水与本期分类支出占比（简化为横向条形，不引图表库）。

## F7 未分类报警表

- 列出所有 `category_id IS NULL` 的流水，按时间倒序。
- 支持行内快速归类（选分类 + 标签后提交），归类成功即从报警表移除。
- 垃圾桶：数量不为 0 时面板高亮提示。

## 二期预留

- `screenshots.status` 预留给 OCR / 多模态识别结果与人工复核。
- `entries.source = auto` 预留给页面 / APK 自动获取。
- 囤货管理建议独立模块（`stock_items` / `stock_movements`），不污染财务流水表。
