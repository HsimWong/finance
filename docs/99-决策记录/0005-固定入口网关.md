# 0005 · 固定入口网关：反向代理而非跳转

- 日期：2026-11-13
- 状态：已上线（网关已发布到 WorkBuddy，固定分享链接可用）
- 触发：cloudflared quick tunnel 每次重启都换 `*.trycloudflare.com` 域名，书签、手机主屏、分享出去的链接全部失效

## 问题

本地程序靠 quick tunnel 暴露时，公网地址是临时的。想给它们一个**不变的地址**，必须有一个本身地址稳定的入口，由它把请求转给当前隧道。

关键前提：**入口自己的地址必须真的稳定。** 如果入口也跑在本地 + quick tunnel，问题只是往后推了一层。

## 决定

1. **入口部署到 WorkBuddy 的「发布为应用」沙箱**，用它的分享链接作为固定地址。沙箱支持单端口 Go 服务、能出网、重新发布保留同一链接。
2. ~~**用反向代理，不用 302 跳转。** 跳转会把地址栏换成随机隧道域名、让 Cookie 跨源失效（`finance_access` 会掉）、坏掉 PWA。~~ **2026-11-14 已改：默认改为门户跳转，见文末「修订」。**
3. **路径前缀挂载**（`/finance/`），不分子域名——WorkBuddy 只提供一个域名，泛解析做不到。
4. **注册表用 JSON 文件而不是数据库。** 注册表是**可重建缓存**：程序每次启动和每 30 秒都在上报，网关重启后一个上报周期内自愈。零第三方依赖，避免沙箱 `go mod` 下载失败。
5. **网关代码零依赖、`go 1.21`**，`net/http` + `httputil.ReverseProxy`。

## 必须处理的四件事（都踩过）

| 问题 | 不处理的后果 | 做法 |
|---|---|---|
| 前端用绝对路径 `/api/x` | 挂到 `/finance/` 下请求打到网关根，全部 404 | 被代理程序改用相对路径 `api/x`；网关对 HTML 的 `href/src/action` 做兜底重写，但救不了内联 `fetch` |
| `GET /finance` 无尾斜杠 | 相对路径以根目录为基准解析，全错 | 301 到 `/finance/` |
| 后端返回 `Location: /` | 用户被带出前缀 | 重写 `Location`：绝对地址换 host 加前缀，相对路径补前缀 |
| Cookie 带上游 Domain / `Path=/` | 浏览器拒绝 trycloudflare 的 Domain；Cookie 漏给其他程序 | 清空 Domain，Path 收拢到 `/{prefix}` |

另外：代理**不走 `HTTP_PROXY` 环境变量**（隧道边缘常被本机代理阻断，与 cloudflared 同一个坑）。

## 验证结果

- 本地：`/finance` 301、API 转发 401→200、静态资源 200、`Location: /finance/`、`Set-Cookie: finance_access=...; Path=/finance`、登录表单 `action` 被重写为 `/finance/__auth`。
- 沙箱：发布成功，`/_gw/health` 200，注册 `https://example.com` 后 `/demo/` 正确返回上游 HTML —— 出网与反向代理链路通。
- WorkBuddy 分享链接需带 `?sharecode=...` 首次访问，它会种 `__wb_rsc` Cookie（30 天，Path=/），之后子请求自动携带。**因此 `GATEWAY_URL` 必须把 sharecode 一起存。**

## 已知风险

- **沙箱会被回收重启（已实测）。** 2026-11-13 23:50 前后 `/_gw/health` 的 `uptime` 从 2m22s 归零、`entries` 回 0，说明进程重起过；但链接未变、请求仍返回 200，是「按需唤醒」而不是持续 502。
  **对策**：服务进程每 60 秒无条件心跳重报（不再只在域名变化时上报），沙箱重启后注册表自动长回来。代价是最长约 60 秒的空窗。
- 备份/回档：网关注册表无需备份，但沙箱重建后要等程序重新上报。
- 只支持路径前缀，不支持子域名。

## 为什么上报放进服务进程（2026-11-14）

原来只在 `start.sh` 的前台循环里每 2 分钟重报，问题有三个：

1. **脚本退出就断供。** 关掉终端、SSH 断开、脚本被 Ctrl+C，固定入口就再也没人更新，域名一换就是死链。
2. **周期是 2 分钟，空窗偏长。** 网关沙箱被回收后，最多要等 2 分钟注册表才长回来。
3. **域名来源靠脚本缓存。** `PUBLIC_URL` 是启动时抓的一次快照，循环里比对才更新。

改成：服务进程自带一个 ticker，每次 tick 直接读 `logs/tunnel.log` 里**最后一个** `*.trycloudflare.com`（cloudflared 重连会追加新域名，旧的随即被回收，所以必须取最后一个），POST 到 `/api/register`。
好处是「只要账本在跑，固定入口就一直在更新」，且与终端/脚本生命周期解耦。`start.sh` 只保留启动时那一次上报，纯为让入口不用等第一轮心跳。

实现要点：

- **快慢两个周期**：域名变化用 5 秒扫描（只读 `logs/tunnel.log`，几乎零成本），变了立刻改报；心跳仍按 `GATEWAY_INTERVAL`（默认 60s）无条件重报，负责让网关沙箱重启后把注册表长回来。实测隧道重启换域名到网关更新只差 **1 秒**（2026-11-14 00:21:16 → 00:21:17）；若只靠 60 秒心跳，这段时间用户会看到 Cloudflare 530。
- **幂等**：同一 prefix 反复上报只是更新 target，重复无害。
- **日志不刷屏**：域名变化打一行；同样的错误只在文案变化时打一次；心跳成功每 30 分钟留一条痕迹。
- **失败退避**：上报失败后 30 秒内不再重试，避免网关挂掉时每 5 秒撞门。
- **查询串位置**：`GATEWAY_URL` 带 `?sharecode=...`（否则沙箱 403），拼接口时要把查询串接在路径后面。
- **代理**：上报目标是公网，走 Go 默认的环境代理；而本机探测隧道域名不能走代理（会 502），所以没做本机探测——上游是否真的活由网关自己的探活判断。

## 修订（2026-11-14 00:30）：默认改为「门户跳转」

用户明确表态：**希望地址栏跳到 cloudflare 域名并且就停在那儿**，「网关只是一个门户网站，只是不用我自己手动点」。

据此把 `GW_MODE` 默认设为 `redirect`：

- 网关首页是一张**门户卡片页**，卡片直接链到程序当前的隧道域名（`https://xxx.trycloudflare.com/`）。
- `/finance` 与 `/finance/` 都返回 **302**（不是 301！301 会被浏览器长期缓存，隧道换域名后用户被钉死在死链上）跳到当前隧道域名，并带 `Cache-Control: no-store`。
- 跳转时**剔掉 `sharecode` / `token`**，不把门户凭据带到隧道域名上。
- 打开后浏览器地址栏就是 `xxx.trycloudflare.com`，之后所有请求直连隧道，**不再经过网关**。因此网关沙箱被回收、注册表被清空，都不影响已经打开页面的人；也不再有「网关指着旧域名 → 530」这个问题。
- 反向代理那套代码保留着，`GW_MODE=proxy` 就回到「地址栏保持网关域名 + 前缀重写」的老行为（`Location` / `Set-Cookie` 改写都还在）。

代价（用户已知情接受）：

- 隧道换域名后，**旧的隧道链接立刻失效**；手机主屏/书签存的是隧道域名就会打不开，存网关链接则每次点一下自动跳新的。
- `finance_access` Cookie 落在隧道域名上，**换一次域名要重输一次口令**。
- 财务系统前端其实已经改成相对路径了，直接访问隧道根路径照样能用，这部分没有白做。

## 血泪：本地进程活不过工具会话

2026-11-14 00:23 出现「全部不通」，排查结果是 `finance.exe` 与 `cloudflared.exe` 都不在了（8081 直接拒连）：从工具里用 `( 程序 & )` 拉起的子进程会在会话结束后被回收。试过 `Start-Process`（PATH 重复键直接报错）、`.NET Process.Start`（安全策略拒绝）、`cmd` 的 `start`（绕过校验被拒），都不通。

**结论：本地服务必须由用户自己的终端拉起——`bash scripts/start.sh`。工具只能负责验证与排障，不能负责常驻。**

## 修订（2026-11-14 00:40）：改用 Windows 计划任务托管，不再需要手动起进程

用户远程访问、无法调出命令行，之前「`scripts/bin/*.exe` 从工具里起的进程会被会话回收」的问题必须根治。

**方案**：进程归 Windows 任务计划所有（`schtasks`），进程树根是 `svchost.exe`，与任何终端会话无关。

- `scripts/supervisor.sh service|tunnel` —— 自愈外壳：服务退出 5 秒重启；隧道退出、拿不到域名、或域名 DNS 未生效时自动换域名重建。
- `C:\Users\WangXin\WorkBuddy\finance-daemon\{service,tunnel}.cmd` —— **纯 ASCII 路径**的入口，计划任务的 `/tr` 里不出现中文路径（避免 GBK/UTF-8 转换把 `财务管理` 弄坏）。
- `schtasks /create ... /sc ONCE /st 00:00 /it` —— 两个任务 `FinanceService`、`FinanceTunnel`。**不能用 `/sc ONLOGON`**（需管理员权限，实测「拒绝访问」）。
- 开机自启：`%APPDATA%\Microsoft\Windows\Start Menu\Programs\Startup\finance-daemon.cmd` 里 `schtasks /run` 两个任务。删除该文件即可关闭自启。
- `scripts/daemon.sh status|start|stop|restart|install|logs` —— 统一控制台。
- `scripts/start.sh` 检测到计划任务存在时会**转交**给 `daemon.sh`：否则 `--stop` 的 `taskkill` 会在 5 秒内被守护进程拉回来，看起来像「停不掉」。
- 停止语义：`daemon.sh stop` 写 `scripts/bin/stop.flag`，守护进程看到后退出，不再拉起。

**实测（00:39）**：同时 `taskkill` 掉 `finance.exe` 与 `cloudflared.exe` → 服务 5 秒起回、隧道 25 秒后拿到新域名 → 上报器 5 秒内改报 → 网关 `/finance/` 302 到新域名 → 登录后首页/`api/meta`/css/js 全 200。

**代价**：`/sc ONCE` 触发器不会自己跑，靠启动文件夹兜；任务只在用户登录时运行（锁屏可以，注销/重启后靠自启项恢复）。
