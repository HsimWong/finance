# 0004 · 库存品类判定：显式选择优先于名称推断

- 日期：2026-11-13
- 状态：已上线（结构版本 v3）
- 触发：试用中录入「别嘌醇缓释胶囊」，在库存页品类显示为「其他」，而不是所选的「药品」

## 现象

库存页「品类汇总」与「库存明细」里，这盒药都显示 `其他`；数据库里却是
`category_key='medicine'`、`category_name='其他'` —— **key 是对的，名字是错的**。
这种自相矛盾的数据还导致汇总按 `(key, name)` 分组时，药品被算进「其他」那一组。

## 根因（两层）

1. **主因 · 后端把显式选择覆盖掉了**
   `saveManualStockItem` 只在 `key == "" && catName == ""` 时才信任输入，但实际逻辑是：
   只要 `catName` 为空，就拿**物品名**去跑 `matchStockRule` 定名称，跑不出就写「其他」；
   而 `key` 保留原值。前端手工入库表单只提交 `category_key`（下拉框），不提交名称，
   于是「选了药品 + 名字里没有『药』字」= key=medicine、name=其他。

2. **次因 · 药品关键词表只认具体药名**
   `stockRules` 的药品关键词是 `布洛芬 / 感冒 / 退烧 / 维生素 / 药 / 口罩 …`，
   「别嘌醇缓释胶囊」一个都不含。即使走「自动判断」也识别不出，
   而具体药名根本无法穷举（厄贝沙坦分散片、头孢克肟颗粒……）。

3. **放大器 · 选错后改不了**
   库存编辑弹窗没有品类字段，`PUT /api/stock/items/{id}` 也不接收 `category_key`，
   用户只能删掉重建。

## 决定

**品类的判定顺序固定为：**

1. 请求给了有效 `category_key`（前端下拉、OCR 草稿）→ **以 key 为准**，显示名从规则表反查；
2. 未给品类 → 按物品名匹配关键词（下一条的剂型词也算关键词）；
3. 显式选「其他」（`key=other`）→ 尊重选择，不再猜；
4. 都推断不出 → 落「其他」。

**药品识别改用「剂型词兜底」**：胶囊、缓释、肠溶、分散片、咀嚼片、泡腾片、含片、片剂、
颗粒剂、冲剂、口服液、滴眼液、软膏、乳膏、凝胶、喷雾剂、栓剂、注射液、糖浆、丸剂、贴膏等，
命中即判药品。同时排除含剂型词的非药品商品：咖啡胶囊、薯片、虾片、麦片、鱼丸、肉丸、奶片。
另外补了一批常见药名（别嘌醇、二甲双胍、阿司匹林、氯雷他定、奥美拉唑、头孢、蒙脱石……）。

**编辑弹窗补品类下拉**，`PUT /api/stock/items/{id}` 接收 `category_key` 并同步纠正名称。

## 数据修复

migration v3（只改数据，不改结构）：

- 对 6 个品类，把 `key` 正确但 `name` 为「其他 / 空」的记录按 key 反查改回正确名称；
- 对 `key ∈ ('', 'other')` 且名称含剂型词的记录，判为药品（同样排除非药品商品）；
- 全部语句带条件判断，重复执行无副作用；升级前自动 `VACUUM INTO` 备份为
  `data/backups/*_before-migration-v3.db`。

## 验证

- 单测：`TestMatchStockRuleMedicine`（10 个药名判药品、6 个含剂型词的非药品不误判、既有品类不被抢）、
  `TestResolveStockCategory`（7 种 key/名称组合）、`TestMigrationV3FixesStockCategoryName`（造 v2 库 → 升级 → 校验修正结果与数据量不变、升级前备份存在）。
- 真实库：`user_version 2 → 3`，`别嘌醇缓释胶囊` 从 `medicine/其他` 变为 `medicine/药品`；
  品类汇总由「其他 1 项」变为「药品 1 项」；1 笔流水、2 条猫用品、10 条预算均无损。
- 接口层：显式选药品 → 药品；不选品类输「厄贝沙坦分散片」→ 药品；「咖啡胶囊」→ 其他；
  显式选其他 → 其他；编辑把「其他」改成药品 → 药品（测试数据用后即删，库存回到 3 项）。

## 遗留

- 剂型词仍是白名单，罕见剂型（如「散」「酊」）可能漏判；手工选品类可即时纠正。
- 若将来要做「药品库存 + 有效期提醒」，建议增加独立的 `medicines` 主数据（通用名、规格、疗程），
  而不是继续堆关键词。
